# System 3 (Agent) Handoff Document

This document outlines everything System 1 (Host Orchestrator / Dashboard) and System 2 (Engine) need to know to integrate `@settle/agent`.

---

## 1. Critical Demo & Validation Notes

> [!IMPORTANT]
> **Auto-approval in the demo depends on the seed having a non-ghost overdue invoice at or below autoApproveMaxAmount.**
> In the standard demo seed fixture, if all non-ghost invoices exceed `policy.autoApproveMaxAmount` (e.g. 50,000 cents / $500.00), those actions will correctly evaluate to `AWAITING_APPROVAL`. To demonstrate automatic approval in the live UI, ensure at least one non-ghost overdue invoice has remaining balance $\le$ `autoApproveMaxAmount`.

> [!NOTE]
> **FakeEngine numbers are canned; validate chat and decisions against the real engine (`--engine real`) once System 2 is merged.**
> `FakeEngine` provides mock forecast numbers and deltas for isolated development and testing. Once System 2 is ready in `@settle/engine`, run the eval suite with `pnpm -F @settle/agent exec tsx scripts/eval.ts --engine real` to verify real mathematical forecasting.

> [!NOTE]
> **Real LLM Adapters Status**:
> The real LLM adapters (`GeminiLlm`, `AnthropicLlm`, `OpenAiLlm`) have been rigorously tested against mock HTTP fetch stubs covering request structure, structured JSON parsing, tool loops, timeouts, and 429/5xx error recovery. Live execution against production APIs requires providing valid API keys in `.env` and running `scripts/liveSmoke.ts`.

## 2. Exports System 1 Must Wire

System 1 constructs and wires the agent using `createAgent` from `@settle/agent`:

```typescript
import { createAgent } from '@settle/agent';

const agent = createAgent({
  engine,           // EnginePort (from @settle/engine)
  llm,              // LlmPort (created via createLlmFromEnv(process.env))
  clock,            // Optional Clock (defaults to new SystemClock())
  idGen,            // Optional IdGen (defaults to new DeterministicIdGen())
  remindersLookup,  // Optional: (invoiceId: string) => number
  policy,           // Optional: Policy override
});

// Run daily cycle
const runResult = await agent.runCycle(snapshot);

// Run chat query
const chatAnswer = await agent.chat(userQuestion, snapshot);
```

### Options Breakdown
- `engine` (`EnginePort`, required): System 2 implementation.
- `llm` (`LlmPort`, required): LLM adapter. Use `createLlmFromEnv(process.env)` to automatically instantiate `MockLlm`, `GeminiLlm`, `AnthropicLlm`, or `OpenAiLlm`.
- `clock` (`Clock`, optional): Clock instance. Use `SystemClock` in production or `FixedClock` in deterministic test runs.
- `idGen` (`IdGen`, optional): Generator for action IDs (`act_...`).
- `remindersLookup` (`(invoiceId: string) => number`, optional): Provides the count of reminders sent for a given invoice in the preceding 7 days. Defaults to `() => 0`.
- `policy` (`Policy`, optional): Global policy override. Defaults to `snapshot.policy`.

## 3. Metadata Convention in Action `reason`

Every `ActionRecord.reason` generated by `runCycle` terminates with a provenance metadata tag:
- **Rule-only Decisions** (ghost payers or empty options):
  ```text
  [via rules; path=rules]
  ```
- **Valid LLM Decisions**:
  ```text
  [via provider=<provider>; model=<model>; path=llm]
  ```
- **Fallback Decisions** (LLM timed out, errored, or produced ungrounded numbers):
  ```text
  [via provider=<provider>; model=<model>; path=fallback]
  ```

## 5. Payer Simulator for Demo Mode

For interactive demos where simulated payers respond to agent actions:

```typescript
import { simulatePayerResponse } from '@settle/agent';

const response = simulatePayerResponse(action, invoice, payer, seed);
// Returns:
// {
//   responds: boolean,
//   accepts: boolean,
//   payAmount: Cents,
//   payDate: ISODate,
//   message: string
// }
```

### Persona Behavior Matrix:
- **reliable**: Pays full remaining balance within 0..2 days on `REMIND`.
- **slow**: Accepts `OFFER_DISCOUNT` with $\ge 2\%$ within 0..3 days; responds to `REMIND` without immediate payment.
- **chronic**: Accepts `OFFER_INSTALMENTS` within 0..2 days (pays first instalment); ignores reminders and discounts.
- **ghost**: Never responds, pays 0.
- **ESCALATE / NO_ACTION**: Never produces a payer response.

## 6. Integer Rounding Rules

To ensure arithmetic parity across all three systems, `@settle/agent` adheres to these rules:

1. **Discount Calculation**:
   ```typescript
   discountedAmount = Math.round(remaining * (1 - discountPct / 100));
   ```
   Uses standard integer round-half-up.

2. **Instalments Remainder Distribution**:
   ```typescript
   base = Math.floor(remaining / count);
   remainder = remaining - (base * count);
   firstInstalment = base + remainder;
   ```
   Any fractional cents remainder is front-loaded onto the first instalment.

## 7. Known Gaps & Deviations

1. **`foldChange` Simulation Fallback**:
   Because `EnginePort` does not currently define an `applyChange` method, `src/foldChange.ts` performs integer-cents state folding. If System 2 later exposes an `applyChange` method on its engine class, the agent automatically detects it via `hasApplyChange()` and delegates to the engine.
2. **`remindersLookup` Default**:
   `Snapshot` does not include historical action logs or reminder counts. The agent defaults to 0 reminders sent in the last week unless System 1 injects `remindersLookup`.
3. **Provider Schema Quirks**:
   - Google Gemini rejects `$schema`, `additionalProperties`, and `title` inside JSON schemas; these are automatically stripped by `sanitizeGeminiSchema`.
   - Anthropic enforces strict tool schema formats; `AnthropicLlm` handles tool definition conversion.

## 8. Contract Change Requests Summary

### Item 1: `ActionRecord.meta` Field
- **Request**: Add optional `meta?: { provider: string; model: string; path: 'llm' | 'fallback' | 'rules' }` to `ActionRecord` in `types.ts`.
- **Reason**: Decouple audit provenance metadata from the human-facing `reason` string.

### Item 2: Reminders History in `Snapshot`
- **Request**: Include `reminderCounts?: Record<Id, number>` on `Snapshot` in `types.ts`.
- **Reason**: Enable self-contained, out-of-band-free reminder policy evaluation for `maxRemindersPerInvoicePerWeek`.

### Item 3: `EnginePort.applyChange` Method
- **Request**: Add `applyChange(input: ForecastInput, change: ScenarioChange): ForecastInput` to `EnginePort` in `ports.ts`.
- **Reason**: Allow the agent to fold approved changes through the engine's canonical accounting model instead of an internal adapter.
